# Talk to the ALSA sequencer through the kernel interface

Supersedes [ADR 0001](0001-shell-out-to-pipewire-and-alsa-tools.md) for ALSA; PipeWire is still read and changed through its tools.

aroute lists ALSA sequencer clients, Ports and subscriptions, and makes and undoes Links, through the ioctls of `/dev/snd/seq`, written in Zig, instead of running `aconnect` or linking libasound. Parsing `aconnect`'s padded, human-oriented text was fragile, its errors came only as text, and it made alsa-utils a dependency; linking libasound would have cost the static, libc-free binary. The sequencer interface is a stable kernel ABI whose parts used here haven't changed in about twenty years, and libasound wraps the same ioctls. The cost is writing the kernel's structures by hand: their sizes, offsets and ioctl numbers are checked against the kernel header at compile time for every target, and tests against the real kernel catch what layouts can't (swapped fields, wrong bits, wrong enumeration). aroute opens one sequencer client, named `aroute`, for as long as it runs, and lists and wires with the same rules and parameters as `aconnect`, so nothing on screen changes. Without a sequencer there is simply no ALSA MIDI, as when `aconnect` failed. This is the base for listening to the sequencer's announce events later, instead of polling.
