# Read PipeWire in the TUI through `pw-dump --monitor`

Supersedes [ADR 0001](0001-shell-out-to-pipewire-and-alsa-tools.md) for reading the PipeWire graph in the TUI; the command-line commands still run a one-shot `pw-dump`, and Links are still made and undone with `pw-link`.

The TUI runs one `pw-dump --monitor --no-colors` for as long as it is up, instead of a one-shot `pw-dump` on every re-read. Each re-read used to start a process and parse the whole graph (about half a megabyte of JSON on a typical desktop) whether or not anything had changed. The monitor writes the whole graph once, then only the objects that change, as partial updates, so aroute folds them by object `id` into the graph it keeps (`monitor.zig`): an update replaces the fields it carries, top-level and within `info`, and keeps the rest; `"info": null` removes the object; a new one goes last, which is where a one-shot `pw-dump` lists it. The Graph is then built from the folded objects by the same code as for a one-shot dump, and is tested to be the same as one from a dump taken at the same moment. Linking libpipewire or speaking its native protocol would have cost the static, libc-free binary, as in ADR 0002. The costs are a process kept running, which must not outlive aroute (it is killed on every way out, Ctrl-C and SIGTERM included), and the monitor hearing of a Link a few milliseconds after `pw-link` returns: after Connect, Disconnect and Load, aroute waits until the monitor shows what it changed, at most a second, before re-reading. If `pw-dump` exits, as when PipeWire stops, the graph is unreadable and aroute starts it again, at most once a second. This is the base for updating the home screen when the graph changes, instead of once a second.
