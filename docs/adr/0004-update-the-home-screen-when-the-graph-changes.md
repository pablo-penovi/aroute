# Update the home screen when the graph changes

Supersedes what is left of [ADR 0001](0001-shell-out-to-pipewire-and-alsa-tools.md): its cost, polling instead of live graph events. PipeWire is still changed through `pw-link`.

The home screen re-reads the graph as soon as it changes, instead of once a second, and does nothing while the graph is still. The TUI waits on the keyboard, the output of the `pw-dump --monitor` it keeps running ([ADR 0003](0003-read-pipewire-in-the-tui-through-pw-dump-monitor.md)), and the sequencer ([ADR 0002](0002-talk-to-the-alsa-sequencer-through-the-kernel.md)). For the sequencer, aroute's client creates one Port that only receives, with no subscribe capabilities and marked no-export so the Midi-Bridge doesn't mirror it, and subscribes the System Announce port (0:1) to it; the kernel then tells it of every client and Port that starts, exits or changes, and every Link made or undone. Polling cost a full re-read every second whether or not anything had changed, and a change made elsewhere took up to a second to show. A woken TUI takes in everything pending from both sources and re-reads at most once, so a burst of changes (a DAW starting up) costs a few re-reads, not one per change. Whether a wake re-reads is the App's decision, not the loop's, so it is tested with a fake Scanner: on the home screen it re-reads; while picking or prompting it only takes changes in, so letters don't move, and coming back home re-reads at once if any came meanwhile. The costs are reading the sequencer's events by hand, including stepping over variable-length ones, which is a pure function tested on byte fixtures and against the real kernel, and still waking once a second while `pw-dump` is down, to start it again.
